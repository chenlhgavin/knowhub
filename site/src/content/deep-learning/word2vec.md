"猫"和"狗"更像，还是"猫"和"桌子"更像？人一眼就知道，计算机不知道——在它眼里，词只是一串互不相干的符号。2013 年的 word2vec 给了机器第一份"语感"：把每个词学成一个几百维的稠密向量，相似的词方向相近，甚至能做算术——经典的 `国王 − 男人 + 女人 ≈ 女王`。

它的核心假设只有一句话：**一个词的含义，由它周围常出现的词决定**。word2vec 就是靠"中心词 ↔ 上下文词"的共现关系，把这句话压进向量。

这是[《一文读懂 BERT》](/knowhub/topics/deep-learning/bert-family)[《一文读懂 sentence-transformers》](/knowhub/topics/deep-learning/sentence-transformers)的前传：BERT 的输入嵌入、SBERT 的对比学习、RAG 的向量检索，血缘都能追回这里。本文由浅入深：前四节讲**原理**（为什么要词向量、靠什么学、模型长什么样、概率怎么算），后三节讲**工程**（怎么绕开算力天坑、怎么备数据、怎么真的训出来），最后看它的天花板怎么引出 BERT（第八节）。

## 一、为什么需要词向量

> 本节回答：词在计算机里本来怎么表示？错在哪？

最朴素的表示是**独热编码（one-hot encoding）**：词表有 N 个词，每个词就是一个 N 维向量，只有自己那一位是 1，其余全 0。它有两个致命问题。

**问题一：不能表达相似度。** 余弦相似度的分子是点积，而任意两个不同词的"1"在不同位置、永不重叠——点积恒为 0。于是"猫和狗"跟"猫和桌子"一样不相关：任意两词互相垂直、距离全都一样，"更像"这件事在数学上根本不存在。

**问题二：太稀疏。** 维度 = 词表大小（几万维），绝大多数位置是 0，存储和计算都低效。

**词嵌入（word embedding）**的方案：把每个词映射成一个**固定长度的稠密向量**（比如 100~300 维，每一维都有值），让"语义相近"体现为"方向相近"——相似度、类比运算从此有了着落。word2vec 就是学这种向量的经典方法。

![独热编码 vs 稠密词向量](/knowhub/images/articles/word2vec/blog-w2v-onehot-vs-dense.png)

## 二、两个模型：Skip-Gram 与 CBOW

> 本节回答：word2vec 靠什么任务学向量？两个模型怎么选？

word2vec 靠"预测共现"来学向量，有两种对偶的做法：

**跳元模型 Skip-gram：用中心词预测上下文。** 给定中心词"猫"，模型要学会给"睡""小""狗"这些常在它周围的词高概率——一个词猜一圈邻居。

**连续词袋 CBOW（Continuous Bag of Words）：用上下文预测中心词。** 给定一圈上下文词，预测中间的词。和 Skip-gram 的唯一结构差异：先把多个上下文词向量**逐维相加再除以个数**，压成一个"综合代表向量"，再走完全相同的流程。

![Skip-gram vs CBOW](/knowhub/images/articles/word2vec/blog-w2v-two-models.png)

> **"词袋"的由来**：平均会丢掉语序——"小猫在睡"和"睡在猫小"的平均向量相同，只关心"有哪些词"、不关心排列，所以叫词**袋**。这个"先平均"的操作后来还会再见：SBERT 的 mean pooling 是它在句子级的同款。

怎么选：Skip-gram 对每个"中心词-上下文词"**逐对**训练，低频词也能被反复训练到，**对低频词更友好**；CBOW 把上下文平均后信号被稀释，但训练更快。后文实现都以 **Skip-gram** 为主线。

## 三、模型结构：浅得惊人，两个矩阵

> 本节回答：这个模型长什么样？词怎么一步步变成分数？

### 1. 每个词有两个向量

每个词同时拥有两个向量：中心词向量 `v`（当"中心词"时用）、上下文词向量 `u`（当"上下文/噪声词"时用）。

> 为什么两个？同一个词既可能当中心词、也可能当别人的上下文，角色不同用不同向量，数学上更干净、训练更稳。最终用哪个（或相加）看实现。

### 2. 参数就是两个矩阵

word2vec 是**只有一层、连非线性激活都没有**的浅网络，全部参数就是两个矩阵——上面两套向量的真身：

```
矩阵 V(中心词矩阵) :|V| 行 × d 列 → 第 i 行 = 词 i 的中心词向量 v
矩阵 U(上下文矩阵) :|V| 行 × d 列 → 第 j 行 = 词 j 的上下文向量 u
```

参数总量 = `2 × |V| × d`。没有别的权重、没有偏置、没有多层。

### 3. 前向计算：查表 → 点积

![Skip-gram 前向：查表 → 点积 → softmax](/knowhub/images/articles/word2vec/blog-w2v-forward.png)

**独热 × 矩阵 = 查表**：独热向量只有一位是 1，乘矩阵 V 恰好取出对应的那一行，其余行全被 ×0 抹掉。所以第一层不是在算乘法，而是按索引**查出词向量**——实现里直接用 embedding lookup，跳过无用的 ×0。查出 `v_c` 后，和 U 的每一行做点积，得到 |V| 个分数：`u · v` 越大，表示两词越该一起出现。

> **反直觉但关键**：训练目标是"预测上下文"，但这只是**借口任务**——我们真正要的是那两个矩阵（词向量）。训练完预测头常直接丢掉，留下的词向量才是成果。这个"借口任务"思想贯穿后来整个预训练时代：BERT 的完形填空同样是借口，要的是练出来的编码器。

## 四、softmax：把分数变概率，和它的天价账单

> 本节回答：分数怎么变成合法概率？训练的代价出在哪？

Skip-gram 的条件概率用 **softmax**：

```
                   exp(uₒ · v_c)
P(o | c) = ──────────────────────────
              Σ  exp(u_w · v_c)      (w 遍历整张词表)
```

三步直觉：**点积当打分**（越大越该共现）→ **exp 变正且拉开差距**（强者更强）→ **除以全词表之和做归一化**（所有词概率加起来 = 1）。一个小例子（中心词 = 猫，词表只有 3 个词）：

```
词      点积    exp(点积)    概率 = exp ÷ 总和
狗      2.0     7.39         7.39 / 9.18 ≈ 0.805
跑      0.5     1.65         1.65 / 9.18 ≈ 0.180
桌子   -2.0     0.14         0.14 / 9.18 ≈ 0.015
              总和 9.18      加起来 = 1.00 √
```

训练目标是**最大化似然**：让真实出现的"中心词-上下文词"对概率尽量大，等价于最小化负对数损失，用随机梯度下降（SGD）+ 反向传播，一个样本改一小步。

**痛点在分母。** 想算**任意一个**词的概率，都得对全词表每个词算一遍 `exp(u_w · v_c)` 再求和——O(|V|)。致命的是每次梯度更新都要重付一遍：

```
词表 |V| ≈ 5 万   更新次数 ≈ 10⁹   每次代价 ≈ |V|
总运算量 ≈ 10⁹ × 5×10⁴ ≈ 5×10¹³   ← 绝大部分算力全花在归一化分母上
```

慢到没法在合理时间内训完。所以需要**近似训练**——把每步的 O(|V|) 换掉。

## 五、近似训练：绕开昂贵的 softmax

> 本节回答：怎么不扫全词表，还能训出一样好用的向量？

### 1. 负采样（Negative Sampling）★最常用

**核心思想：把"从全词表里选对的词"这个多分类问题，变成一堆二分类问题。** 真实的"中心词-上下文词"对是正例（标签 1）；再随机采 K 个不在窗口里的词当**噪声词**（负例，标签 0）。模型只需反复回答一道是非题："这个词是不是中心词的真实上下文？"

![负采样：多分类变二分类](/knowhub/images/articles/word2vec/blog-w2v-negative-sampling.png)

损失是 `−log σ(正例点积) − Σ log σ(−负例点积)`（σ 是 sigmoid），**复杂度从 O(|V|) 降到 O(K)**，K 通常取 5~20——不再算完整分母，只看正例加十几个负例。

两个实现细节，各藏一个洞察：

- **噪声词按 `P(w) ∝ 词频^0.75` 采样。** 对小于 1 的频率开分数次方，原本越小的数被抬升越多——"劫富济贫"：次方 = 1 完全按词频（高频词垄断负例），次方 = 0 完全均匀（无视词频），0.75 是试出来的折中。
- **怎么 O(1) 抽样**：训练前建一张约 10⁸ 格的大数组（unigram table），每个词按 `P(w)` 占相应比例的格子，抽负例时随机取一个下标即可。**10⁸ 是格子数，不是词数**——同一个词占很多格（the 可独占几千万格）。格子远多于词是故意的：分辨率 1/10⁸ 够小，让最罕见的词也能占 ≥1 格、不被舍成 0；再大则内存吃不消（10⁸ 个 int ≈ 400MB）。精度与内存的折中。

> 前瞻：这套"正例拉近、负例推远"的哲学，六年后在 SBERT 的对比学习里原样重演——只是单位从"词对"换成了"句对"。

### 2. 层序 softmax（Hierarchical Softmax）

另一条路：用一棵**二叉树**组织词表，每个叶节点 = 一个词。把"从 |V| 个词里选 1 个"换成"沿树往下走，每个岔路口做一次二选一"，岔路口只有 log₂|V| 个：

```
                 n1  ← 根(内部节点,带向量 θ)
               /    \
            n2        n3          叶 = 词,内部节点 = 岔路口决策器(各带一个 θ)
           /  \      /  \
         n4   n5   n6   n7
        / \   / \  / \  / \
      w1 w2 w3 w4 w5 w6 w7 w8    ← 8 个词,树深 = log₂8 = 3

P(w3│c) = σ(θ_n1·v_c) × (1−σ(θ_n2·v_c)) × σ(θ_n5·v_c)   ← 只乘 3 项,不碰其他词
```

每个岔路口用 sigmoid 决定往左往右（左 `σ(θ·v_c)`、右 `1−σ(θ·v_c)`，左 + 右 = 1），词的概率 = 根到叶路径上各岔口概率的乘积，复杂度 **O(log|V|)**。

> **为什么天然归一化**：每个岔路口"左 + 右 = 1"，概率像**水流**——从根的 1.0 往下分，每次分叉两股之和不变，最终流进所有叶子的总量必然还是 1。省掉的正是那个 O(|V|) 分母。

| 方法 | 复杂度 | 特点 |
|---|---|---|
| 原始 softmax | O(\|V\|) | 精确，但太贵 |
| **负采样** | O(K) | 简单灵活、可调 K，**最常用** |
| **层序 softmax** | O(log\|V\|) | 二叉树，自动归一化 |

后文的数据准备与训练都用**负采样**。

## 六、工程落地（一）：数据准备

> 本节回答：一堆生文本，怎么变成能喂给模型的规整批量？

以 **PTB（Penn Tree Bank，华尔街日报语料）**为例：出现少于 10 次的词记 `<unk>`，词表约 6719 个词。流水线四步：**下采样 → 提词对 → 负采样 → 打包**。

### 1. 下采样（subsampling）高频词

"the / 的"这种高频词跟谁都共现，提供的信息少还拖慢训练。于是每个词以一定概率被**丢弃**，越高频越容易被丢：

```
丢弃概率 P(w) = max(1 − √(t / f(w)), 0)     (f(w) = 词频比例,阈值 t = 1e-4)
```

高频词 f 大 → √(t/f) 小 → 丢弃概率接近 1；低频词 f ≤ t 时被 max 截成 0，一个不丢。效果："the" 从 50770 次砍到约 2056 次（丢约 96%），低频词几乎完整保留——给"刷屏词"限流，共现信号更干净。

### 2. 提词对 + 负采样

对每个中心词**随机**取 1~max 的窗口大小，窗口内的词都算它的上下文词（正例），PTB 共产出 150 多万对；再给每个上下文词配 K=5 个噪声词（按 `词频^0.75` 采样，且不能撞上该中心词的真实上下文）。

> **别混淆：下采样 vs 负采样**——都带"采样"、都涉词频，但方向相反，是**接力不是二选一**：下采样是**减法**（从语料里丢掉高频废词，数据清洗，靠前做），负采样是**加法**（给每个正例配 K 个噪声词，近似训练，靠后做）。同一个高频词角色相反：下采样里被丢弃，负采样里优先被选作负例。

![下采样 vs 负采样](/knowhub/images/articles/word2vec/blog-w2v-subsample-vs-negsample.png)

### 3. 小批量打包：三个关键数组

样本长短不一（窗口随机 → 上下文数量不同），但矩阵必须规整，于是用 0 填充对齐，并引入三个逐位对齐的数组：

```
                     └上下文┘ └──噪声词──┘ └填充┘
contexts_negatives:  5   8   3   9   1   7   0   0   ← 上下文+噪声拼接,尾部补0
labels           :   1   1   0   0   0   0   0   0   ← 答案:上下文=1(正),其余=0(负)
masks            :   1   1   1   1   1   1   0   0   ← 真假:真数据=1,填充=0
```

**精髓：为什么 labels 之外还要 masks**——`label=0` 有两种，靠 mask 区分：噪声词是**真负例**（mask=1，要算损失）；填充 0 是**硬凑的**（mask=0，不算损失，否则模型会去学根本不存在的数据）。即 **labels 管"对/错"，masks 管"真/假"**，缺一不可。批量 512、每样本填充到 60，打包成三个 512×60 的规整矩阵。

## 七、工程落地（二）：实际训练 Skip-Gram

> 本节回答：代码里这些概念各自对应什么？损失怎么算？

### 1. 嵌入层：两个矩阵的代码版

**嵌入层（embedding layer）就是第三节那个"查表矩阵"的封装**：报一个词 id，直接返回矩阵对应行。Skip-gram 用**两个**嵌入层，正好对应"每个词两个向量"——`embed_v` 存中心词向量，`embed_u` 存上下文向量；同一个词在两层里各占一行，是两个不同的向量。

### 2. 前向传播：一次点积打完 60 个分

中心词和候选词是两个独立输入（中心词每样本恒 1 个，不参与 padding）：

```
embed_v(centers)            → v  (512,  1, 100)   中心词向量
embed_u(contexts_negatives) → u  (512, 60, 100)   候选词向量(上下文+噪声+填充)
bmm(v, uᵀ)                  → 打分 (512, 1, 60)
```

这个 bmm（批量矩阵乘）本质就是"1 个中心词 vs 60 个候选词，各点积一次 → 60 个分数"：矩阵乘把 60 次点积一次算完，bmm 再让 512 个样本各算各的、互不串门。得到的分数正好配上打包好的 `labels` 和 `masks`，送进损失。

### 3. 损失函数：带掩码的二元交叉熵

**把它想成给一套是非题判分**：60 个候选词 = 60 道"它是不是中心词的上下文？"，损失 = 这份答卷的"错误分"。

- **sigmoid** 把点积分数（任意实数）压到 0~1，解读成"是上下文的把握 p"；
- **BCE（Binary Cross-Entropy）判分**：`label=1` 损失 `−log(p)`、`label=0` 损失 `−log(1−p)`——答对且自信扣分少，越自信却答错罚越狠（真答案 = 1 时，答 p=0.9 损失约 0.1，答 p=0.1 损失约 2.3），自信答错处梯度大，向量被使劲往对的方向拽。

![sigmoid 与 −log 损失曲线](/knowhub/images/articles/word2vec/sigmoid-and-loss.png)

再叠加两点工程处理：**mask** 让填充位损失 ×0（作废题不计分）；**规范化**把损失 ÷ 真题数，让长短样本可比。而这正是负采样损失的代码实现——按标签展开逐项对上（用了 `1−σ(x) = σ(−x)`）：

```
正例(label=1):−log(p)   = −log σ(点积)     ← 负采样损失第 1 项
负例(label=0):−log(1−p) = −log σ(−点积)    ← 负采样损失第 2 项
```

数学写法 vs 工程写法，同一件事。

### 4. 训练与应用

优化器 Adam，监控规范化损失和 tokens/sec；训完后 **`embed_v` 的每一行就是一个词的最终词向量**（`embed_u` 通常丢弃）——借口任务落幕，成果交接。用余弦相似度取 top-k 就能找近义词，`国王 − 男人 + 女人` 的最近邻就是`女王`。

## 八、天花板与去向

> 本节回答：word2vec 做不到什么？后来的故事往哪走？

**天花板一：一个词永远只有一个向量。** word2vec 学出的是**静态**词向量——本质是一张查完即得的表，不看上下文。"a crane is flying"（鹤）和 "a crane driver came"（吊车）里的 crane 共用同一个向量，一词多义无解。

**天花板二：它只交付一张表。** 词怎么组合成句子的含义（语序、否定、谁修饰谁），word2vec 一概没学——每个下游任务还得自己搭网络、用自己的小数据从零训练"读懂句子"这件事。

这两个天花板，正是 2018 年 BERT 的起点：让同一个词在不同句子里得到不同向量，并把整个"理解主干"作为预训练成果交付下游——详见[《一文读懂 BERT》](/knowhub/topics/deep-learning/bert-family)；而"把一整句话装进一个向量"的后续，在[《一文读懂 sentence-transformers》](/knowhub/topics/deep-learning/sentence-transformers)。

> **一句话收尾**：word2vec 用一个"预测上下文"的借口任务，逼模型把语义相近的词学成方向相近的向量；真正的工程难点不在模型（它浅得只有两个矩阵），而在绕开 softmax 那个 O(|V|) 的分母——负采样把它变成廉价的二分类，这才让它在几十亿词的语料上训得动。词语第一次变成了向量，后面的一切 embedding，都从这里出发。
