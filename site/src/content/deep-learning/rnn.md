"小明 出生 在 法国……他 说 一口 流利 的 ___"——你几乎不假思索地填出"法语"。让计算机也学会这样"接话"，靠的是**语言模型**；而第一个真正能"带着记忆读句子"的神经网络，叫 **RNN**（Recurrent Neural Network，循环神经网络）。

它要解决的矛盾一句话能说清：**想记住历史，又不能让参数爆炸。** 死记硬背的方案记得越多参数越多，注定走不远；RNN 的答案是不存历史本身，只存一个**固定大小、不断更新的"记忆账本"**。今天大语言模型"读到哪、记到哪"的直觉源头，就是这本账本。

本文由浅入深：先看序列数据特殊在哪、文字怎么变成数字（一、二节），再看传统"数频率"方案怎么撞墙（三节），然后是主角 RNN 的原理与训练（四、五节），最后拆开它的两大顽疾——梯度爆炸与消失（六、七节），看它的天花板怎么引出 LSTM 与注意力（八节）。

## 一、序列数据：顺序本身就是信息

> 本节回答：股价、文字这类数据，和一张图片有什么本质不同？

一张图片打乱像素还能重排回来，一句话打乱字序就面目全非——"狗咬人"和"人咬狗"，字一样，意思相反。股价、天气、音乐、文字都属于**序列数据**：**前后相关、顺序不能动，过去决定未来。**

麻烦跟着就来：想预测第 t 个值，理论上要看它之前的**全部历史**，而历史越来越长，没法喂给固定结构的网络。把"看不完的历史"压成"固定大小的输入"，有两条思路：

| 思路 | 做法 | 本质 |
|---|---|---|
| **自回归** | 只看最近 τ 个：`P(x_t \| x_{t-1},…,x_{t-τ})` | 马尔可夫假设，输入定长，普通 MLP 就能吃 |
| **隐变量自回归** | 记一个会更新的账本：`h_t = g(h_{t-1}, x_{t-1})` | **RNN 的前身**——账本大小固定，却浓缩全部历史 |

> 打个比方：你不需要背下今年每一天的开销，只要心里记一个不断更新的账本——来一笔新账，就更新一下账本。

无论哪条思路，都躲不开同一个限制：**单步预测准，多步预测会崩。** 预测远期时只能拿自己的预测当输入，误差滚雪球式累积——d2l 的实验里，预测 4 步还不错，64 步直接退化成一条没用的常数线。根因是分布漂移：模型从没见过"自己预测出来的那种输入"。

## 二、把文字变成数字

> 本节回答：模型只认数字，一篇文章怎么变成一串数？

所有文本任务的第一步都是一条四步流水线：

```
读取(清洗) → 词元化 tokenize → 建词表 Vocab(词↔编号) → 转索引 → 语料库 corpus
```

词元（token）切多细是第一个选择：**单词级**语义完整但词表巨大、还有查不到的新词；**字符级**词表极小、几乎没有未知词，代价是序列变长。入门实验通常选字符级图省事——科幻小说《时光机器》整本书变成 170580 个字符索引，词表只有 28 个（26 个字母 + 空格 + 未知符 `<unk>`）。

词表本质是一本**双向字典**（词 ↔ 编号）：按词频排序编号、低频词过滤掉、查不到的统统记到 `<unk>` 那一页。这一步做完，文字就成了模型能吃的数字序列。

## 三、先试试笨办法：数频率的 n 元语法

> 本节回答："猜下一个词"的传统方案是什么？为什么注定走不通？

**语言模型 = 给定前文，猜下一个词。** 它还附赠一个能力：给整句话的概率打分。链式法则把整句概率拆成 `P(x_1,…,x_T) = ∏ P(x_t | 前文)`——把一句话从头走到尾，把每一步真实出现的那个词拿到的概率连乘起来，就是整句话的概率。概率高的更"像人话"：语音识别里"你好"和"泥嚎"发音相同，语言模型算出前者概率高得多，就选它。

实际计算不直接连乘，而是取 log 把连乘变加法：100 个词、每词概率 0.01，整句概率 10⁻²⁰⁰，早低于 float32 能表示的下限、会被舍入成 0（下溢）；取 log 后变成普通负数相加。再加个负号得到 **`−log P`（意外值）**：猜对为 0，越离谱越大——这正是交叉熵损失。

![−log p：概率变意外值，连乘变加法](/knowhub/images/articles/rnn/neglog_surprise.png)

那么 `P(下一个词 | 前文)` 从哪来？最朴素的答案是**数频率**——这就是 **n 元语法**（n-gram）：套用马尔可夫假设只看前 n−1 个词，比如 `P(learning|deep)` = "deep learning" 出现的次数 ÷ "deep" 出现的次数。

它的死局用一个迷你语料就能完整走一遍。设全世界的语料只有 4 句话、词表 10 个词：

```
① 我 爱 吃 苹果   ② 我 爱 吃 香蕉   ③ 他 爱 喝 咖啡   ④ 她 讨厌 喝 咖啡
```

用三元语法（看前 2 个词）挨个验证：

- **数频率**：`P(苹果|爱 吃)` = "爱 吃 苹果"次数 ÷ "爱 吃"次数 = 1/2；
- **确实更准**：二元只看见"爱"，把三句话的经验搅在一起（`P(吃|爱)=2/3、P(喝|爱)=1/3`）；三元多看一个词就分清了语境——`P(吃|我 爱) = 1`、`P(喝|他 爱) = 1`，从"三七开地猜"变成"笃定"；
- **但表在指数膨胀**：要为"每种前缀 × 每个下一个词"都留一个计数格子，三元表 10×10×10 = 1000 格（二元才 100）——**n 每加 1，格子数就多乘一个词表大小**。换成真实的 1 万词表，三元就是 10¹² 个格子；
- **而且填不满（稀疏）**：16 个词的语料只数得出 7 种三元组，1000 格里 993 个是 0。给完全合理的新句"她 爱 喝 咖啡"打分：`P(喝|她 爱) = 0/0`——"她 爱"碰巧没出现过，一个 0 因子把整句概率干成 0，模型宣称这句话"不可能出现"；
- **平滑救不了**：拉普拉斯平滑给所有计数加个小常数保底，`P̂(喝|她 爱) = 1/10`，句子得救；可胡说八道的"她 爱 苹果"算出来**也是 1/10**。人能从"'他 爱 喝'出现过，他/她是近义词"推出"她 爱 喝"必然合理——计数表里"他""她"只是两个无关编号，**经验无法迁移**。

更糟的是，语言本身就和数频率过不去。**齐普夫定律**：把词按频率排名，频率 ∝ 1/排名^α——极少数词超高频（the、of、and），绝大多数词都躺在低频长尾上，log-log 坐标下是一条笔直的线，而且一元、二元、三元词组全都满足：

![齐普夫定律：线性坐标看长尾，log-log 坐标看直线](/knowhub/images/articles/rnn/zipf_law.png)

这意味着"没见过、数不准"不是例外，而是**常态**：数频率的前提是数得够多，可长尾里的词和词组几乎数不到；组合空间又是词表的平方、立方，观测被稀释得更狠。**死记硬背没有出路，需要能把经验从"他"迁移到"她"的模型——能"学关系"的神经网络。**

## 四、RNN：给网络装一本记忆账本

> 本节回答：怎么用一个固定大小的东西，记住任意长的历史？

![记住历史的两种方式](/knowhub/images/articles/rnn/blog-rnn-ngram-vs-rnn.png)

RNN 用两条公式取代那张天文数字的计数表：

```
记忆更新：H_t = tanh( X_t·W_xh + H_{t-1}·W_hh + b_h )
输出：    O_t = H_t·W_hq + b_q
```

> 打个比方：`H_{t-1}` 是你昨天的笔记，`X_t` 是今天发生的事，一套固定的规则把两者合成今天的新笔记 `H_t`；要做判断时，翻今天的笔记（`W_hq`）。

沿时间把它展开，结构一目了然：

![RNN 沿时间展开](/knowhub/images/articles/rnn/blog-rnn-unroll.png)

两个关键性质：

**其一，参数全时间步共享。** `W_xh、W_hh、W_hq` 三套权重在每个时间步都是同一套——所以**序列再长，参数量都不变**。n 元语法"记得越多参数越多"，RNN 记多久都是这一套参数，"循环"二字正来源于此：同一个计算被一遍遍套在每个时间步上。

**其二，激活函数必须有，而且偏偏选 tanh。**

- **没有非线性就白循环**：去掉 tanh 往前代两步，`H_2 = X_2·W_xh + X_1·(W_xh·W_hh) + H_0·W_hh²`——展开到任意步都只是"输入乘固定矩阵再相加"，循环 100 步的表达能力等于一步的线性模型；
- **tanh 是限幅器**：同一个 `W_hh` 要被反复乘几十上百次，数值稍偏大就滚雪球（每步放大 1.2 倍，50 步 ≈ 9100 倍）。tanh 把输出压回 [-1,1]，记忆刚要膨胀就被摁回框里；
- **ReLU 在这里是反面教材**：上不封顶（雪球没人踩刹车）、负区归零（记忆通道一断永断）。前馈网络怕"越传越弱"所以用 ReLU；RNN 怕"越滚越大"，需要刹车不是油门。

**怎么衡量模型好坏？** 语言模型的标准指标是**困惑度**（perplexity）= exp(平均交叉熵)，直观含义 ≈ **模型每一步平均在几个候选词之间纠结**。它的来历很简单：`exp(−log P) = 1/P`——每步给正确词 1/P 的概率，等价于在 1/P 个词里均匀猜。比如每步都给正确词 1/4 的概率，平均损失 log 4 ≈ 1.386，困惑度 exp(1.386) = 4，正好还原出"4 个候选词"。

| 模型状态 | 每步给正确词的概率 | 困惑度 |
|---|---|---|
| 完美 | 永远 = 1 | **1**（零纠结） |
| 均匀瞎猜 | 1/词表大小 | **词表大小**（及格线） |
| 最坏 | 0 | ∞ |

字符级词表 28，瞎猜线就是 28；训好的字符级 RNN 约 1.2~1.3——"每步只在 1.3 个字符间轻微犹豫"。**损失给优化器看（好求导），困惑度给人看（有"候选词个数"这个单位）**，两者是同一信息的两种记法。

## 五、训练：跟着一个小批量走一遍

> 本节回答：这套公式在代码里怎么跑起来？

设字符级词表 5 个字符（编号 0~4），批量取 2 条子序列、各 3 个时间步，完整走一遍：

![训练一个小批量的完整旅程](/knowhub/images/articles/rnn/blog-rnn-train-flow.png)

**① 采样切批**：从语料切出特征 `X = [[2,4,1], [0,3,1]]`，标签是 `X` 整体右移一位——每一步的任务都是"看当前字符，猜下一个"。

**② 独热 + 转时间步优先**：编号之间没有大小意义，先变成 one-hot 向量；再把 `(批量, 时间步)` 转置成 `(时间步, 批量, 词表)`，让循环每次取出"所有样本在同一时刻"的输入。

**③ 前向循环**：`H` 初始化全 0，逐时刻更新：

```python
for X_t in inputs:                          # t=0, 1, 2 依次
    H = tanh(X_t @ W_xh + H @ W_hh + b_h)   # H 被反复覆盖 = 记忆逐步传递
    outputs.append(H @ W_hq + b_q)          # 这一步对词表的预测得分
```

**④ 算损失**：所有时间步的输出拼起来，和标签算 softmax 交叉熵。

**⑤ 反向 + 裁剪 + 更新**：`backward()` 算出梯度 → 梯度裁剪（下一节）→ `step()` 更新参数，顺序不能乱。

**⑥ 下一批的 `H`**：随机采样时批间不连续，`H` 清零重来；顺序分区时批间在原文相邻，`H` 传下去接着用，但要 **detach** 砍断计算图——否则反向传播会一路回溯到 epoch 开头（这就是第七节的"截断 BPTT"）。

**训练完怎么用？** 给个开头如 `"time traveller"`：**预热期**逐字喂入、只更新 `H` 不输出，让空白记忆先"读入状态"；**生成期**每步取概率最高的字符，再把它当作下一步的输入，自回归逐字续写。

## 六、梯度裁剪：训练 RNN 的安全带

> 本节回答：为什么训练 RNN 几乎必加梯度裁剪？

梯度就像导航给的"方向 + 步子大小"。RNN 反向传播时同一个 `W_hh` 被连乘很多遍，数值稍大于 1、乘几十遍就指数放大——步子迈得离谱，参数被一把推飞，loss 变 NaN，训练当场崩。

梯度裁剪是个**限速器**。把所有参数的梯度拼成一个大向量 `g`：

```
g ← min(1, θ/‖g‖) · g        （阈值 θ 通常取 1）
```

没超速（`‖g‖ ≤ θ`）原样放行；超速了就等比例缩回到长度恰为 θ——**方向一点不变，只压幅度**：

```python
def grad_clipping(net, theta):
    params = [p for p in net.parameters() if p.requires_grad]
    norm = torch.sqrt(sum(torch.sum(p.grad ** 2) for p in params))  # ‖g‖
    if norm > theta:                                                # 超速才动手
        for p in params:
            p.grad[:] *= theta / norm                               # 等比例缩回
```

注意它只治"爆炸"——把过大的梯度压回来；**治不了"消失"**：太小的梯度已经没了，没法凭空放大。两种病的共同根源，就在下一节。

## 七、BPTT：爆炸与消失的总根源

> 本节回答：梯度到底怎么沿时间传播？为什么必然出问题？

**BPTT**（Backpropagation Through Time，通过时间反向传播）没有新原理：把循环沿时间步摊平成一条长链，照常做链式法则。问题就出在这条链上。

用一个能手算的极简 RNN 看清楚。矩阵退化成标量、去掉激活函数：`h_t = w·h_{t-1} + x_t`，求 `∂h_3/∂w`。`w` 影响 `h_3` 有两条路——它自己直接出现在式子里（直接项），它还藏在 `h_2` 里（间接项）。两条路相加，得到递归式，一路代到底：

```
∂h_3/∂w = h_2 + w·h_1 + w²·h_0      ← 隔了几步，就乘几个 w
```

![BPTT 的要害：同一个 w 连乘](/knowhub/images/articles/rnn/blog-rnn-bptt.png)

序列长到 50 步，来自第 1 步的贡献要背上 `w⁴⁹`：

- `w = 1.2`：1.2⁴⁹ ≈ **7600** —— 早期项被放大几千倍，**梯度爆炸**（第六节的裁剪治它）；
- `w = 0.8`：0.8⁴⁹ ≈ **0.00002** —— 早期项几乎归零，**梯度消失**。

消失比爆炸隐蔽得多：消失的不是整个梯度，而是**来自早期时间步的那些项**——训练不崩、loss 照降，但模型**只从最近几步学东西**。回到开头那句话："小明 出生 在 **法国** ……（中间 40 个词）…… 他 说 一口 流利 的 ___"——猜"法语"靠的那条关联带着 `w⁴⁰`，早就消失了，模型永远学不会。**这就是"RNN 记不住长期依赖"的准确含义。** 而且消失没法像爆炸那样"裁"回来：爆炸是太大压小（信息还在），消失是信息已经没了、你不知道它本来该是多少——只能换架构。

真实 RNN 里 `w` 换成矩阵 `W_hh`，命运由它特征值的绝对值 `|λ|` 主导：**>1 爆炸，<1 消失**——时间一长，几乎不可能恰好卡在 1。

实践的标配是**截断 BPTT**：既然越早的项要么爆炸要么没用，干脆只往回传最近 τ 步：

```
完整：∂h_50/∂w = h_49 + w·h_48 + w²·h_47 + … + w⁴⁹·h_0     （50 项）
截断：∂h_50/∂w ≈ h_49 + w·h_48 + … + w⁹·h_40               （只留 10 项）
```

实现就是第五节那个 `H.detach()`：数值留下（前向的记忆照传），计算图砍断（反向到此为止）。至此，训练流程里的两个"补丁"——梯度裁剪和 detach——都补上了"所以然"。

## 八、天花板与下一站

> 本节回答：RNN 做不到什么？路通向哪里？

把全文串成一条线：

- **序列数据**前后相关、顺序不能动，预测要靠"记住历史"；
- **n 元语法**死记硬背，参数指数膨胀 + 长尾稀疏，撞墙；
- **RNN** 用固定大小的隐状态 `H` 总结无限历史，参数靠全时间步共享锁死——这是它对"核心矛盾"的漂亮回答；
- 但 **BPTT 的连乘**判了它另一个刑：梯度消失让它**记不住太久以前的事**。裁剪治得了爆炸，治不了消失。

于是接力棒交了出去：**LSTM / GRU** 用门控给梯度修一条不易衰减的通路，让"该记的记得久"；再后来，**注意力机制**干脆放弃"把历史压进一个固定账本"，让每个位置直接回看全部历史——那就是 Transformer 的故事了。

> **一句话收尾**：RNN 第一次证明了"用固定大小的记忆装下任意长的历史"是可行的——它的成功（参数共享 + 隐状态）和它的失败（连乘导致的梯度消失），共同定义了之后十年序列建模的进化方向。
